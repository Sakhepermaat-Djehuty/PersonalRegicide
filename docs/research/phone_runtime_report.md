## 1.3 `ui` module — exact API (from official reST source, confirmed by stubs)
**Threading model (verbatim from "About Actions and Delegates"):** "all callbacks are called on the main (UI) thread of the host app." A long-running callback makes the app appear frozen. "Other callback methods can be `decorated` to run in the background" with `@ui.in_background`. Delegate methods that *return* a value must run on the main thread.
- `ui.in_background(fn)` — "Call a function on the main interpreter thread." "This is useful to perform long-running tasks from an action or delegate callback without blocking the UI." Also needed for functions that cannot run on the UI thread, e.g. `console.alert`. Typically used as a decorator. (Doc wording is inconsistent: "main interpreter thread" vs "regular interpreter thread" — meaning: the script's own thread, *not* the UIKit main thread.)
- `objc_util.on_main_thread(fn)` exists (Beta notes build 160022: "New `on_main_thread` function, mostly intended to be used as a decorator"; reentrant since build 160023). Beta notes build 160032: "All functions in the `console` and `dialogs` modules should be safe to call from the main thread now."
- Gotcha (issue #780, Jul 2025, 15 comments): setting `label.text` inside a button action and then doing more work in the same callback shows only the final text — the callback runs to completion on the main thread before UIKit redraws. Remedy: do the slow work in `@ui.in_background` and set UI attributes from there (ui attribute setters are marshalled to the main thread), or split via `ui.delay`.
- **View.present** — `present(style='default', animated=True, popover_location=None, hide_title_bar=False, title_bar_color=None, title_color=None, orientations=None, hide_close_button=False)` (the `hide_close_button` param is in the Amoosekerrason stub and current docs; the 2016 docset omits it). Styles documented: `'full_screen'` ("The presented view covers the entire screen") — the intro spells it `'fullscreen'` and community code universally uses `'fullscreen'`; `'sheet'` (iPad only; "covers a roughly quadratic area in the middle of the screen"); `'popover'` (iPad only; `popover_location` is a screen-coordinate point where the arrow points, default top-right); `'panel'` (sliding panel beside the console); `'sidebar'` (next to editor, width ≤ 200 pt). "On the iPhone, all views are presented in full-screen." `orientations` (list such as `['portrait']`) applies only to full-screen presentation; default all. With `hide_title_bar=True` the view is closed via **two-finger swipe-down** or `View.close()`. `'default'` is never defined in the docs (behaves as fullscreen on iPhone, sheet on iPad in practice **[UNVERIFIED]**).
- `View.wait_modal()` — "waits until the view is no longer on screen"; **returns immediately if called from the main thread** (e.g. inside an action) or if the view is not on screen. `View.close()`. `View.will_close()` — called just before a presented view is dismissed ("good place to save data"). `View.did_load()` — after loading from a `.pyui` file. `View.layout()` — called when the view is resized. `View.draw()` — "called when the view's content needs drawing"; never call directly; call `View.set_needs_display()`.
- **Touch handling:** override `touch_began(self, touch)`, `touch_moved(self, touch)`, `touch_ended(self, touch)` on a `ui.View` subclass. `Touch` attributes (read-only): `location` (x, y) in the owning view's coordinates; `prev_location`; `phase` ∈ `'began' | 'moved' | 'stationary' | 'ended' | 'cancelled'`; `touch_id` (int, stable across events); `timestamp` (ms since 1970). `View.multitouch_enabled` (False → only first touch delivered); `View.touch_enabled`. There is **no built-in gesture-recognizer API in `ui`** (community `gestures` module via `objc_util` exists **[UNVERIFIED]**); taps/drags are implemented from the touch callbacks.
- **View attributes:** `name, frame, bounds, center, x, y, width, height, alpha, hidden, background_color (None = transparent), border_color, border_width, corner_radius, content_mode, flex, multitouch_enabled, touch_enabled, transform (ui.Transform; frame undefined while set), superview, subviews, on_screen, tint_color`; methods `add_subview, remove_subview, remove_from_superview, bring_to_front, send_to_back, size_to_fit, set_needs_display, update_layout`. `flex` is a string of letters: `W` flexible width, `H` height, `L` left margin, `R` right, `T` top, `B` bottom; `""` disables autoresizing ("WH" fills superview; "TR" anchors bottom-left).
- **Controls:** `Button(title=, image=, background_image=, font=, title_color=, action=, enabled=)` — action receives `sender`; `Label(text, font, text_color, alignment, number_of_lines (0 = unlimited), line_break_mode)`; `ImageView(image, content_mode)`; `ScrollView(content_size, content_offset, content_inset, paging_enabled, scroll_enabled, bounces, zoom_scale/min/max, delegate.scrollview_did_scroll(sv))`; `TableView(data_source, delegate, row_height, reload_data(); ListDataSource(items, action, edit_action, delete_enabled, move_enabled))`; `TextField, TextView, WebView (load_url/load_html/eval_js), NavigationView(root_view).push_view(view, animated=True)/pop_view(animated=True), Switch, Slider, SegmentedControl, ActivityIndicator, DatePicker`.
- **Fonts:** tuples `(font_name, font_size)`, e.g. `('<system>', 20)`, `('<system-bold>', 16)`, `('Helvetica', 14)`; any iOS font name works.
- **Drawing (inside `draw()` or an `ui.ImageContext`):** `ui.set_color(color)` (CSS name / hex / RGBA tuple / gray float); `ui.Path.rect(x, y, w, h)`, `ui.Path.oval(...)`, `ui.Path.rounded_rect(x, y, w, h, corner_radius)`; instance methods `move_to, line_to, add_arc(cx, cy, r, start_angle, end_angle[, clockwise=True]), add_curve, add_quad_curve, add_clip, append_path, close, fill(), stroke(), hit_test(x, y), set_line_dash(seq, phase)`; attrs `line_width, line_cap_style, line_join_style, eo_fill_rule, bounds`; `ui.draw_string(string, rect=(0,0,0,0), font=('<system>', 12), color='black', alignment=ui.ALIGN_LEFT, line_break_mode=ui.LB_WORD_WRAP)`; `ui.measure_string(string, max_width=0, font=..., alignment=..., line_break_mode=...)` → (w, h); `ui.Image.named(name)` (built-in icon names without extension, e.g. `'ionicons-beaker-256'`, `'iob:…'`, `'emj:…'`, `'typb:…'` prefixes **[prefix list UNVERIFIED]**, or a local file path with extension); `ui.Image.from_data(bytes[, scale])`; `Image.draw(x, y, w, h)`, `.size`, `.scale`, `.to_png()`, `.resizable_image(top,left,bottom,right)`, `.with_rendering_mode(mode)`; `with ui.GState():` saves/restores drawing state; `with ui.ImageContext(w, h, scale=0) as ctx: ... ctx.get_image()` for off-screen rendering (e.g. pre-render card faces once and cache as `ui.Image`).
- **Scheduling / animation:** `ui.delay(func, seconds)` (**func first, seconds second** — note the PythonIDE/pyboot stub reverses this), `ui.cancel_delays()`, `ui.animate(animation_callable, duration=0.25, delay=0.0, completion=None)` (animatable View attributes: frame/alpha/transform/background_color…), `ui.Transform.rotation(rad)/.scale(sx, sy)/.translation(tx, ty)`.
- **Other:** `ui.load_view([path])` loads `.pyui` from the bundled UI designer; `ui.get_screen_size()` → (w, h) points; `ui.get_window_size()` (differs in iPad split view); constants `ALIGN_LEFT/CENTER/RIGHT/JUSTIFIED/NATURAL`, `CONTENT_SCALE_TO_FILL/SCALE_ASPECT_FIT/SCALE_ASPECT_FILL/REDRAW/CENTER/TOP/…`, `KEYBOARD_*`, `LINE_CAP_*`, `LINE_JOIN_*`, `LB_WORD_WRAP/CHAR_WRAP/CLIP/TRUNCATE_HEAD/TAIL/MIDDLE`.
- **Lifecycle:** a presented view stays on screen after the script's main thread finishes; callbacks keep working **[high confidence, not in docs text I read]**. App backgrounding suspends the script; there is no documented foreground/background callback in `ui` other than `will_close` → persist state after every move.

## 1.4 `scene` module — exact API (official reST source)
- "an easy way to create hardware-accelerated 2D graphics and animations, specifically games." Backed by SpriteKit (not stated in text; `SKExample.py`, `.pysk` particle files in omz's samples). **Origin bottom-left**, sizes in points; `get_screen_scale()` → 2.0/3.0; `get_screen_size()` → Size.
- `scene.run(scene, orientation=DEFAULT_ORIENTATION, frame_interval=1, anti_alias=False, show_fps=False, multi_touch=True)` — presents the Scene full-screen; `PORTRAIT`/`LANDSCAPE` force orientation and disable auto-rotation; `frame_interval=2` → 30 fps (default 60). The docs do **not** say whether `run()` blocks (in practice it returns when the scene view is closed — treat as blocking **[UNVERIFIED]**).
- **Embedding in `ui`:** `scene.SceneView` is a `ui.View` subclass with attrs `scene` (settable), `paused`, `frame_interval`, `anti_alias` ("4x multisampling… sometimes significant performance cost, disabled by default"), `shows_fps`, `multi_touch_enabled`. "To embed a scene, create a SceneView, set its `scene`, and add it to a ui view hierarchy." `Scene.view` is the presenting View (None if not presented). stdout/exceptions appear in a status line at the bottom of the SceneView.
- **Scene callbacks:** `setup()` (once; `size`/`bounds` valid), `update()` (every frame before actions, unless paused), `draw()` (classic render loop only), `touch_began(touch)`, `touch_moved(touch)`, `touch_ended(touch)`, `did_change_size()`, `pause()/resume()/stop()` (home button / return from background / "x" button), `present_modal_scene(other)`, `dismiss_modal_scene()`, `did_evaluate_actions()`. Attributes: `size`, `bounds` (origin 0,0), `t` (seconds since start), `dt` (seconds since last update), `touches` (dict touch_id → Touch), `background_color`, `view`, `safe_area_insets` (newer), `physics_world`.
- **Nodes:** `Node(position=(0,0), z_position=0.0, scale=1.0, x_scale=1.0, y_scale=1.0, alpha=1.0, speed=1.0, parent=None)`; attrs `position, rotation, alpha, z_position, x_scale, y_scale, frame, bbox, children, parent, paused, scene, speed`; methods `add_child, remove_from_parent, run_action(action[, key]), remove_action(key), remove_all_actions(), point_from_scene(pt), point_to_scene(pt), child_named(name)`. `SpriteNode(texture=None, position=…, size=None, color='white', blend_mode=0, …)` attrs `anchor_point (default (0.5,0.5)), size, texture, color, color_blend_factor, blend_mode, shader`. `LabelNode(text, font=('Helvetica', 20), **node_kwargs)` attrs `text, font, color, alignment` (changing text/font regenerates the texture). `ShapeNode(path=None, fill_color='white', stroke_color='clear', shadow=None, **kw)` attrs `path (ui.Path), fill_color, stroke_color, shadow=(color, dx, dy, radius)`; line width comes from the `ui.Path.line_width`. `EffectNode` (post-processing; `crop_rect, effects_enabled, shader`), `EmitterNode(particle_file)`. `Texture(name_or_ui_Image)`, `.subtexture(unit_rect)` (sprite sheets share GPU data), `.filtering_mode` (`FILTERING_LINEAR` default, `FILTERING_NEAREST` for pixel art), `.size` in pixels.
- **Actions:** `Action.move_to(x, y[, duration, timing_mode])`, `move_by(dx, dy, …)`, `scale_to/scale_by/scale_x_to/scale_y_to(s, …)`, `rotate_to/rotate_by(radians, …)`, `fade_to/fade_by(alpha, …)`, `sequence(*actions)`, `group(*actions)`, `repeat(action, count)` (count ≤ 0 → forever), `repeat_forever(action)`, `wait(seconds)`, `call(func[, duration])`, `set_uniform(name, value, …)`, `remove()`; default duration 0.5 s; timing modes `TIMING_LINEAR (default), TIMING_EASE_IN, TIMING_EASE_IN_2, TIMING_EASE_OUT, TIMING_EASE_OUT_2, TIMING_EASE_IN_OUT, TIMING_SINODIAL, TIMING_ELASTIC_IN/OUT/IN_OUT, TIMING_BOUNCE_IN/OUT/IN_OUT, TIMING_EASE_BACK_IN/OUT/IN_OUT`.
- **Classic render loop (scene_drawing):** override `draw()` (~60 fps, nothing persists between frames) and call `background(r,g,b)`, `fill(r,g,b,a)`, `no_fill()`, `stroke(r,g,b[,a])`, `no_stroke()`, `stroke_weight(w)`, `tint()/no_tint()`, `rect(x,y,w,h)`, `ellipse(x,y,w,h)`, `line(x1,y1,x2,y2)`, `triangle_strip(points[, tex_coords, image_name])`, `image(name, x, y, w, h[, from_x, from_y, from_w, from_h])`, `image_quad(...)`, `text(txt, font_name='Helvetica', font_size=16.0, x=0.0, y=0.0, alignment=5)`, `load_image(name)`, `load_image_file(path)`, `load_pil_image(pil_img)` (RGBA only), `render_text(txt, font_name, font_size)` → (name, size), `unload_image`, `translate/rotate(deg)/scale/push_matrix/pop_matrix/blend_mode/use_shader`. Docs: "it is strongly recommended to use the new Node/Action APIs instead" — "significantly better performance." Known bug (issue #796, Jan 2026, linked to old #149): in the classic loop, `stroke()` color changes are ignored when only `line()` is drawn until an ellipse/rect is drawn with the new color (workaround: draw an off-screen ellipse).
- Scene `Touch(x, y, prev_x, prev_y, touch_id)` with `location`, `prev_location`, `touch_id` (no `phase`).

## 1.5 Persistence
- Scripts live in `~/Documents` = Files app location **"On My iPhone/iPad → Pythonista 3"**, or the iCloud container (**"iCloud Drive → Pythonista 3"**) — both appear in the Pythonista file browser; `os.environ['HOME']` points to the shared folder (beta notes build 160025). Plain file I/O, `json`, `sqlite3`, `pickle` all work; a per-campaign JSON file written after every action is the simplest robust persistence (surviving app kills). Pythonista 3.3+ can also bookmark folders outside its sandbox via **"EXTERNAL FILES → Open… → Folder…"** (e.g. a Working Copy repo or SMB share; discussion #136 notes an SMB-added prefix may change and require re-bookmarking).
- `keychain` module for secrets; `clipboard` module for copy/paste.

## 1.6 Packages / pip
- No C-extensions can be added (iOS forbids loading compiled plugins not shipped with the app). Pure-Python only, three routes: (1) **StaSh** (`import requests as r; exec(r.get("https://bit.ly/get-stash").content)` → `launch_stash.py`; its `pip` installs "pure Python packages from PyPI"; in 2026 StaSh PR #524 (merged ~2026-07-30) made it bootstrap *real* pip from `https://bootstrap.pypa.io/get-pip.py` and rewrite calls to the correct `--target`; `pip show/list/install/remove` tested; packages needing subprocess-based builds still fail); (2) **pipTerminal** (`import requests as r; exec(r.get('https://tinyurl.com/Setup-pipTerminal').content)`; "C extensions are not allowed on iOS"; needs `<pkg>-<ver>-py3-none-any.whl`); (3) **Pipista** (touch-first package manager, Aug 2026, "deliberately cautious and aimed mostly at pure-Python packages", can download public GitHub repos as editable projects). Issue #797 (Feb 2026) "[BUG] pip support is broken again" — recurring breakage: get-pip installs to the home dir, `/pylib/lib` is read-only, `--prefix`/`shutil` hacks stopped working; `--target` partly works; "when downloading binary wheels they cannot be executed" (o-murphy, 2026-08-07). A stray old `ctypes` in `site-packages-3` broke StaSh (Aug 2026) — delete it. **Implication:** keep the game engine dependency-free (stdlib only) — nothing to install.
- Bundled interpreter path example: `Py3Kit.framework/pylib/...`; user packages go in `~/Documents/site-packages` (StaSh) / `site-packages-3`.

## 1.7 Getting code onto the phone
- **Working Copy (git client, Files-provider):** the discussed workflow (discussion #133, Jul–Aug 2026): VS Code → push to private GitHub repo → Working Copy pulls on iOS. "Free mode cannot push iOS changes" (push is a paid unlock). Store the local repo in "On My iPad/Pythonista 3/" so both apps see the same folder (RichardPotthoff); after a pull, swipe-away and restart Pythonista so file contents reload. Alternative: commit edits on github.com in Safari with a hardware keyboard. Working Copy x-callback-url usage with `pythonista3://…?action=run` appears in community sync scripts (tdamdouni/Pythonista `Working_Copy_Sync-ahenry91.py`) **[details UNVERIFIED]**.
- **No-git pull script (recommended for an AI-agent loop):** a 30-line `update.py` using the bundled `requests`/`urllib` + `zipfile` to download `https://github.com/<user>/<repo>/archive/refs/heads/main.zip` (or a release tarball) and unpack into `~/Documents/<app>` — no pip, no Working Copy; same approach Forge-patcher's installer uses (`urllib` from `raw.githubusercontent.com`). For a private repo, store a fine-grained token with the `keychain` module.
- **iCloud Drive:** put files in the "Pythonista 3" iCloud folder from a Mac/`Files`; discussion #133 notes you cannot import a whole folder tree via the in-app importer and large files sometimes crashed restart.
- **"Open in Pythonista" / URL scheme (official `urlscheme` doc):** `pythonista3://` (3.x-specific; `pythonista://` undefined if both 2 and 3 installed). `pythonista3://Folder/ScriptName` opens the script in the editor (`.py` optional); `?action=run` runs it ("only if no script is already running"); only scripts already in the library can be run. Arguments: `args=foo%20bar` (space-split, double-quote to keep spaces) → `sys.argv == [<script_path>, 'foo', 'bar']`; or repeated `argv=foo&argv=bar` (each one element; if any `argv` present, `args` is ignored). Community-used extra: `&root=icloud` to target the iCloud folder (cvpe's tool) **[UNVERIFIED in official docs]**. `shortcuts.pythonista_url(path='', action='run'|'open'|'exec', args=None, argv=None)` builds such URLs; `shortcuts.open_url(url)`; `shortcuts.open_shortcuts_app(name=None, shortcut_input='')` (3.3+ `shortcuts` module).
- **Shortcuts app:** Pythonista provides a **"Run Pythonista Script"** action (discussion #136; issue #795 "crash when script is run via Shortcuts"). Inputs are materialised as temp files in a `ShortcutInputTemp` directory that is never cleaned up (issue #798: grew to ~6 GB) — delete it from your script if you pass large inputs. Exact parameter→`sys.argv` mapping of that action **[UNVERIFIED]**. `run_script.py` (discussion #136) shows the pattern of a launcher that `runpy.run_path(target, run_name='__main__')` after fixing `sys.path`/cwd — useful for launching from a bookmarked external folder; note "there seems to be an extra argument appended at the end when called from pythonista tools".
- **Home-screen launch:** (a) Shortcuts → "Run Pythonista Script" → share sheet "Add to Home Screen" (standard iOS; gives a custom icon) **[standard iOS feature, from memory]**; (b) cvpe's "Add home screen shortcut.py": serves a local HTML page with `apple-mobile-web-app-capable` + `apple-touch-icon` to Safari (`webbrowser.open('safari-http://localhost:<port>')`), user taps Share → Add to Home Screen; the web clip redirects to `pythonista3://<script>?action=run[&root=icloud][&argv=…]` when `navigator.standalone` is true; (c) the editor "wrench" menu shortcuts + 3D-Touch/long-press quick actions on the app icon (beta notes 160033/160036).
- **App extension / widget:** `appex` module (`is_running_extension()`, `get_text()`, `get_url()`, `get_image()`, `get_file_path()`, `finish()`), Today widget (`appex.set_widget_view(view)`; Python 3 only, limited modules, tight memory).

# 4. Pure web app (HTML/JS or PWA) in Safari → Home Screen
- **Installability on iOS:** Safari's Share → "Add to Home Screen". MDN: since iOS/iPadOS 16.4 PWAs can also be installed from Chrome/Edge/Firefox/Orion; `beforeinstallprompt` is **not** supported on iOS; installed PWAs appear in App Library but not in Settings' app list; removing the icon deletes the PWA (and its storage). Manifest essentials (Chromium's list, also respected by Safari): `name`/`short_name`, `icons` (192 + 512 px), `start_url`, `display` (`fullscreen → standalone → minimal-ui → browser` fallback chain); HTTPS required (GitHub Pages is HTTPS). A service worker is **not** required for installability but is what provides offline.
- **Safari 26.0 (iOS 26, released 2025-09-15):** "Added support for any website to become a web app on iOS or iPadOS. (113034903)" and "Fixed the 'Add to Home Screen' flow failing to load webpage data, preventing users from making new Home Screen web apps. (154655565)". Safari 27 (2026-09-14) ships with iOS 27; 27.0 notes include IndexedDB fixes and Cookie Store `maxAge`, nothing new on web-app install.
- **Storage (MDN "Storage quotas and eviction criteria"):** Safari on macOS 14 / iOS 17+: per-origin quota "around 60% of total disk" for browser apps (15% for apps embedding web content), overall cap 80% (20% embedded); localStorage ~5 MiB per origin (general browser rule); IndexedDB/Cache API/OPFS share the big quota. **Eviction:** "If an origin has no user interaction, such as click or tap, in the last seven days of browser use, its script-created data is deleted" (WebKit ITP 7-day cap on all script-writable storage: localStorage, IndexedDB, Cache API, service-worker registrations). `navigator.storage.persist()`: Safari "automatically approve[s] or den[ies] the request" from interaction history, no prompt. **Home-screen web apps:** WebKit's tracking-prevention page states home-screen web apps are "exempt from ITP's 7-day cap on all script-writeable storage" (quoted by two third-party docs; the Feb-2024 EU change that removed that exemption was reverted in March 2024) **[UNVERIFIED directly — webkit.org unreachable]**; MDN only says a Home Screen app "uses the same origin quota as the browser app". Practical rule: install to Home Screen, call `persist()`, and give the player an explicit **Export/Import save (JSON file / clipboard)** so campaign state is never only in browser storage.
- **Offline:** inline everything in one `index.html` (JS + CSS + base64 assets) plus a tiny service worker that caches `index.html` (and, for Pyodide, its ~6–7 MB of assets) with cache-first strategy; or rely on Safari's HTTP cache (unreliable). Single-file HTML can also be opened from Files/AirDrop, but then it has no origin for storage persistence — host on **GitHub Pages** from the repo instead.
- **Pros vs Pythonista:** no paid/aging app dependency, zero install friction, shareable link, works on any phone/desktop, trivially screenshot/CI-testable with Playwright, animations easy (CSS/Canvas). **Cons:** game logic would be JavaScript/TypeScript (unless §5), storage-eviction risk, no file system (export via download/share), Safari quirks (100vh, rubber-banding, double-tap zoom — set `touch-action: manipulation`, `user-scalable=no`).

# 5. Python-in-the-browser PWA (Pyodide / PyScript / MicroPython / Brython)
- **Pyodide** (github.com/pyodide/pyodide): latest release **314.0.7 (2026-09-14)** on the new CPython-version-numbered line (314.0.0, 2026-06-09, "Upgraded to Python 3.14.2"); maintenance lines **0.29.5** (2026-09-15; 0.28.0 = CPython 3.13.2) and 0.27.8 (0.27.0 = 3.12.7). The changelog never explains the parallel numbering; PyScript 2026.7.3 bundles 314.0.3, so 314.x is the mainstream line. Release assets: `pyodide-core-314.0.7.tar.bz2` **6.44 MB** (`pyodide-core-0.29.5.tar.bz2` 5.71 MB) = the minimal runtime: `pyodide.mjs` (preferred; `pyodide.js` legacy), `pyodide.asm.mjs`, `pyodide.asm.wasm`, `python_stdlib.zip`, `pyodide-lock.json` ("Necessary in all cases"); full package bundle `pyodide-314.0.7.tar.bz2` **322 MB** (0.29.5: 389 MB) — not needed for a stdlib-only engine. CDN: `https://cdn.jsdelivr.net/pyodide/v<version>/full/pyodide.mjs` (debug variant `/debug/`); self-hosting needs correct WASM MIME type + CORS headers (GitHub Pages serves `application/wasm` correctly **[from memory]**); jsDelivr serves Brotli (changelog 0.23: 20–30% smaller). Browser download of core is roughly 3–5 MB compressed / ~12 MB uncompressed **[estimate, UNVERIFIED]**; first start on a modern iPhone ~2–4 s, cached starts ~1 s **[UNVERIFIED]**.
  - **Safari/iOS history:** "Pyodide had been broken on iOS since 0.27.1 because of faulty wasm-gc support on that platform" (fixed 0.27.3); 0.28.0 fixed a regression "that crashed Pyodide on iPad and Safari"; "The full test suite is now run in Safari" since 0.22.0. Use ≥ 0.27.3 / 0.28+/314.x.
  - **Workers:** "Pyodide requires a module-type worker because `pyodide.asm.mjs` is an ES module… Classic workers using `importScripts()` are not supported" (`new Worker("./webworker.mjs", {type: "module"})`); message-passing with ids; "long-running synchronous Python work can block the UI when run on the main thread" — for a card engine (microseconds per action) running on the main thread is fine. Service worker usage is documented (static import of `pyodide.asm.mjs`, pass as `createPyodideModule`, because "service workers forbid dynamic `import()`") but is not needed for offline caching — a plain cache-first SW for the asset files suffices.
  - **Loading your engine:** `pyodide.loadPackage("https://…/regicide-1.0-py3-none-any.whl")` ("The file name must be a valid wheel name", no dependency resolution) or `await micropip.install("./regicide-1.0-py3-none-any.whl")` (string ending `.whl` treated as URL; `deps=False` to skip resolution; server must send CORS headers if cross-origin); or fetch a zip and `pyodide.unpackArchive(buf, "zip")` then `sys.path.insert`; or `pyodide.FS.writeFile`. Persistence inside Python: MEMFS is lost on reload; mount IDBFS (`pyodide.FS.mkdirTree("/mnt"); pyodide.FS.mount(pyodide.FS.filesystems.IDBFS, {}, "/mnt")`) and call `pyodide.FS.syncfs(...)` — simpler: have Python return the save as a JSON string and let JS store it in localStorage/IndexedDB and offer file export.
- **PyScript** (github.com/pyscript): release **2026.7.3 (2026-07-29)**, "updated Pyodide to version 314.0.3"; CDN `https://pyscript.net/releases/2026.7.3/core.css` + `<script type="module" src="https://pyscript.net/releases/2026.7.3/core.js">`; `<script type="py" config="./conf.json" src="./main.py">` (or `type="mpy"` for MicroPython); config keys `interpreter` (pin or custom URL, e.g. `"https://cdn.jsdelivr.net/pyodide/v0.29.0/full/pyodide.mjs"`), `files` (`{"./code.py": "./subdir/code.py"}`), `packages`, `js_modules`; JSON config avoids an extra TOML-parser download; `from pyscript import when, display` and `@when("click", "#id")` for DOM events. **Offline:** "Since late 2025, each PyScript release includes an offline zip with everything needed" (first mentioned in 2025.11.2 notes); copy `pyodide*` files + `python_stdlib.zip` + `pyodide-lock.json` to `public/pyodide` and set `interpreter: "/pyodide/pyodide.mjs"`; workers need Cross-Origin-Isolation headers (serve with `mini-coi`) — **GitHub Pages cannot set COOP/COEP headers**, so avoid PyScript workers / SharedArrayBuffer and run on the main thread. **MicroPython** option: "Compressed for delivery, it's only about 170KB"; subset of stdlib, no package installs — a dependency-free engine written to the common subset could run on MicroPython for near-instant load, but you lose `dataclasses`/`typing` richness and exact CPython parity; test both in CI if you go this way.
- **Brython** (github.com/brython-dev/brython): 3.15.0 via jsDelivr (`brython.min.js` + `brython_stdlib.js`), "implements the Python version of the same major/minor version number" since 3.8; transpiles Python→JS in the browser; no C extensions, stdlib subset "not relevant in the browser context" excluded; `<script type="text/python">`. Faster first load than Pyodide, but it is not CPython: subtle semantic differences mean the engine tested under pytest is **not** the engine that runs on the phone. Not recommended for parity.

# 9. Recommendation (concrete)
1. **Architecture (do this regardless of UI target):** `regicide/` pure-stdlib package (no third-party deps, **Python 3.10 syntax/stdlib only** — avoid `typing.Self`, `tomllib`, `except*`, `StrEnum`, `datetime.UTC`, `kw_only` is OK since 3.10), fully deterministic (seeded `random.Random`), with a **command → event/view-model API**: `Game.apply(command: dict) -> list[event dict]`, `Game.view() -> dict` (JSON-serialisable), `Game.to_json()/from_json()`. Campaign/legacy state is a separate JSON document layered on top. pytest on Linux with a CI matrix of **3.10 and 3.13/3.14** so both phone targets are covered. Add a scripted "random legal-move bot" test to shake out rule bugs.
2. **Primary UI: Pythonista 3 (`ui` module), thin renderer** over `Game.view()`: a single custom `ui.View` subclass that draws the board in `draw()` with `ui.Path`/`ui.draw_string`/pre-rendered card `ui.Image`s (cache via `ui.ImageContext`), handles `touch_began/ended` for tap-to-select and drag-to-play, `present('fullscreen', hide_title_bar=True, orientations=['portrait'])`, saves JSON to `~/Documents/regicide_saves/` after every command and in `will_close()`. Use `@ui.in_background` only for anything slower than a few ms (not needed for this engine); use `ui.animate`/`ui.delay` (or a `scene.SceneView` with `Action.move_to` + `LabelNode`/`SpriteNode`) if you want card-flight animations later. Pass-and-play = a "hand off to player N" cover screen between turns.
3. **Delivery loop that needs the user only once:** commit a `pythonista/update.py` that downloads the repo zip from GitHub (`requests`, bundled) into `~/Documents/Regicide/` and a `pythonista/main.py` launcher; the user copies `update.py` once (paste from GitHub in Safari, or iCloud), runs it, then adds a Shortcut "Run Pythonista Script → main.py" to the Home Screen. If the repo is private, store a token with `keychain.set_password`. Working Copy is the alternative for users who already own it (free tier pulls; restart Pythonista after pulling).
4. **Fallback/parallel: PWA** (`web/index.html` + `sw.js` + the engine wheel, published to GitHub Pages) loading **Pyodide 314.x** from jsDelivr (or self-hosted core files, ~6.4 MB tar.bz2) on the main thread, calling `Game.apply`/`Game.view` through `pyodide.runPython`, rendering with plain DOM/CSS; `navigator.storage.persist()`, JSON save in localStorage + export/import. This gives an app-store-free alpha on any device and a CI-screenshotable UI (Playwright) without touching the phone — valuable when the user is unavailable. Do not use PyScript workers on GitHub Pages (no COOP/COEP headers).
5. **Gates where the user is needed:** (a) confirm Pythonista 3 is installed/updated and on which iOS (3.4 / Python 3.10.4 expected); (b) run `update.py` once and add the Home-Screen shortcut; (c) report device-specific issues (Safe Mode flag, screen size `ui.get_screen_size()`); (d) optionally pay for Working Copy push or supply a GitHub token for private-repo pulls; (e) optional: enable GitHub Pages for the PWA.
